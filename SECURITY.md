# Security Policy

## Credential & Secret Handling

- Cinder **never** stores API keys, tokens, chat histories, or local model weights inside project workspaces or Git repositories.
- Provider credentials and persistent application state live strictly in the OS application data directory (`%LOCALAPPDATA%\Project_Bumbo\state.json` on Windows, `~/Library/Application Support/Project_Bumbo/state.json` on macOS, `~/.local/share/Project_Bumbo/state.json` on Linux, or `$CINDER_DATA_DIR`), protected with strict user-only permissions (`0o700` directory / `0o600` file on Unix).
- Sensitive credentials (`settings.api_keys` secrets and `mcp_servers[*].env` values) are encrypted at rest before writing `state.json` (Windows DPAPI `dpapi:v1:` on Windows; HMAC-SHA256 authenticated `sealed:v1:` vault key with `0o600` permissions on Unix), and legacy plaintext values are transparently migrated on load.
- Runtime artifacts (`target/`, `release/`, `.bumbo/`, `.cinder/`, `state.json`, `knowledge_index.json`, `.env*`, key files, and `*.gguf` binaries) are excluded via [`.gitignore`](.gitignore).

## Runtime Isolation & Defense-in-Depth

- **Network Gate, DNS Pinning & Redirect/DNS SSRF Guards (`harness-net`, `harness-tools`):** When set to `Strict Local Mode`, all outbound non-loopback HTTP requests and HTTP redirects (`Location` hops) are rejected before socket creation, and all allowed/blocked requests are logged to the Network Audit trail. Models cannot change network privacy mode via tool calls (`switch_mode` accepts work modes only). `fetch_url` resolves DNS ahead of connection, blocks loopback/private/link-local/CGNAT (`100.64.0.0/10`)/`0.0.0.0/8`/ULA/site-local/NAT64/6to4 ranges, pins validated socket addresses per hop (`request_no_redirect_pinned`) to stop DNS rebinding, and re-validates every manual redirect hop.
- **Workspace & Scratchpad Path Sandbox (`harness-tools/src/sandbox.rs`, `harness-tools/src/packages.rs`):** All workspace and standalone session scratchpad file tools resolve paths through `resolve_workspace_path`, which rejects off-root UNC/network paths, Windows alternate data streams (`:`), and out-of-workspace absolute paths lexically **before** issuing filesystem calls, and validates every path component via `symlink_metadata` so parent traversal (`..`), outside symlinks, and **dangling symlinks** cannot escape the root. Tar/zip extraction validates archive entries and symlink targets.
- **Strict Loop Allowlists, Workspace Trust & Untrusted Instruction Framing (`harness-core`):** Every agent, sub-agent (`delegate_research`), and Orchestrator loop (`run_agent_loop`, Phase 1 Planner, Phase 2 Executor) rejects undeclared tool calls and restricts read-only planners/sub-agents strictly to read-only tools before dispatch. Orchestrator edits require review before execution by default (`review_before_execute: true`) and honor `auto_approve_edits`. Repository instruction files (`.cinder/rules.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.agents/rules/*.md`) are **not** loaded into the system prompt unless the user explicitly trusts the workspace folder (`trusted_workspaces`), and even when trusted remain isolated inside `<untrusted_workspace_instructions>` tags with an explicit non-escalation policy.
- **File Launch, Config-Write, Sandboxed Previews & MCP Hygiene (`harness-tools`, `cinder-gui`):** `open_url_safely` strictly allows `http`, `https`, and `mailto`; `open_with_system_default` blocks symlinks and dangerous executable/script extensions (`exe`, `bat`, `cmd`, `ps1`, `vbs`, `hta`, `lnk`, etc.) and uses Win32 `ShellExecuteW` without shell interpolation; `html_widget` browser previews strip `<script>`, `<base>`, and `<meta http-equiv="refresh">` tags and render inside a `sandbox=""` `iframe` with `script-src 'none'; connect-src 'none'` CSP; writes to `.git/*`, `.cargo/config*`, `.vscode/*`, `.cinder/rules.md`, `.agents/rules/*`, or `mcp_config.json` always escalate to manual approval; workspace-imported MCP servers default to disabled and `mcp-git`/`mcp-fetch` always require approval; and Git probes force `core.fsmonitor=false`, `core.pager=cat`, `diff.external=`, and `protocol.file.allow=never`.
- **Tool Approval Gates, Binary Checksums, Install Hardening & Opt-In Runtimes (`harness-tools`, `harness-models`):** `classify_tool_risk_with_context` inspects both `"command"` and `"cmd"` keys and normalizes all path aliases/wrappers (quotes, backticks, `@`, `file://`, `%20`, trailing dots/spaces) consistently with the sandbox; `SafeReadOnly` commands exclude code-executing checks (`py_compile`, `pytest`, `git diff --no-index`, `--ext-diff`, `-C`, colon-bound path params); RAG indexing/search (`build_workspace_index`, `search_workspace_knowledge_with_policy`) excludes secret files for cloud models; sensitive API tokens are scrubbed from shell, MCP, and package-install child environments; Portable Node.js LTS (`SHASUMS256.txt`) and `llama-server` GitHub release downloads fail closed unless SHA-256 checksum verification succeeds; npm/pip installers pass `--ignore-scripts` and `--only-binary=:all:`; and opt-in `run_local_software` runtimes stay disabled by default, require manual approval, clear child env, block `.bat`/`.cmd`/`.ps1` wrappers, inline eval flags, and `=`-attached traversal, and terminate OS process trees on timeout.

## Reporting a Vulnerability

If you discover a security issue, privacy leak, or sandbox bypass in Cinder, please report it responsibly by opening a private security advisory or contacting the repository owner at <https://github.com/cruellophon/cinder_dev/security>.
